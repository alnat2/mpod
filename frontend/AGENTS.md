## Проверка

- После UI-изменения выполни реальную browser verification против актуального Figma source.
- Проверь затронутые состояния и desktop/mobile breakpoints, а не только один screenshot.
- Настраивай настоящий browser viewport. Изменение CSS width у body не заменяет viewport для media queries.
- Не объявляй задачу готовой, если required visual verification не выполнена; сообщи, что мешает.
- Если обнаружен backend/API дефект вне frontend scope, сообщи evidence и не реализуй backend fix без разрешения.

## Hard Verification Gates (Визуальный контроль UI)

1. **Скриншот экрана в сборе перед стартом (Figma Reference):**
   - Перед редактированием любого экрана или лейаута агент обязан выгрузить изображение экрана целиком на целевом брейкпоинте через Figma MCP (`get_screenshot`, например `546:2209` для десктопа или `885:6375` для мобилки) и сохранить в артефакты.
   - Запрещено ориентироваться только на изолированные компоненты без сверки сетки, взаимного выравнивания (start vs center) и отступов экрана в сборе.

2. **Ограничения юнит-тестов (Unit Tests ≠ UI Verification):**
   - Прохождение `npm run test` валидирует только логику API, контракты пропсов и состояние React.
   - Замоканные тесты (например, с подменой `EpisodeRow` или `PodcastCard` на упрощенные `<div>`) не проверяют CSS, flexbox, grid, скругления и адаптивность. Запрещено использовать зелёные тесты Vitest как свидетельство визуальной готовности вёрстки.

3. **Обязательный скриншот реального браузера перед сдачей (No Silent Skip):**
   - Агент не имеет права объявлять UI-задачу готовой, коммитить или пушить код без снятия реального скриншота из браузера на целевом разрешении (1440x900 десктоп / 360x800 мобилка).
   - Если запуск headless браузера не удается из-за песочницы, агент ОБЯЗАН запросить выполнение вне песочницы (`BypassSandbox: true`), а не отчитываться о сдаче.
   - Выполнить прямое сопоставление (side-by-side) скриншота браузера с макетом Figma: выравнивание по сетке, ориентация карточек, разнесение колонок и отступы.
